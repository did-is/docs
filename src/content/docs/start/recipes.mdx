## Prerequisites and evidence labels

- Use a fresh working directory, Node.js 24 or newer, curl and Python 3.10 or newer. No account or API key is needed for these public API routes.
- For the TypeScript tabs, install **published `@didis/client` 0.2.5** (`npm install @didis/client@0.2.5`); for Python, install **published `didis-py` 0.2.5** (`python -m pip install didis-py==0.2.5`). Save each tab under the filename shown. Run TypeScript with `node resolve.ts`, `node credential.ts` or `node authorize.ts`; Python with `python resolve.py`, `python credential.py` or `python authorize.py`. These examples do not use unpublished SDK fields.
- Set `BASE` to the API base URL you intend to call, including `/api` for the hosted service: `export BASE='https://did.is/api'`. Programs refuse to run if it is missing. A successful HTTP response is not an acceptance decision.
- **A — executed:** these exact example programs were run against the current local engine over real HTTP on 2026-10-31 UTC, with the published SDK artifacts. This is not a production availability test or a paid API test.
- **B — stored snapshot:** expected fields below describe that dated run, not a continuously live result. Times, generated DIDs, digests and latency will differ when you repeat it.
- **C — illustration / not run:** business domains and diagrams on the use-case page illustrate integration ideas. They are not customers or evidence of successful onboarding, payments or monitoring.

Public requests use the free per-client budget: **20 requests/minute standard; intensive requests also consume a separate 10 requests/minute budget**. The SDKs retry `429` according to `Retry-After`; curl does not automatically retry here. Wait the returned seconds before repeating. [Paid API keys](/app/accounts/) use team allowances and different routes; these recipes exercise neither paid entitlements nor billing.

## Generate the synthetic inputs

Save as `make-inputs.mjs`, then run `node make-inputs.mjs` before the credential and agent recipes. It uses only Node's built-in cryptography. New Ed25519 keys stay in memory; seven JSON request files are written. Regenerate after one hour (the signed inputs expire). **Never use these synthetic claims or receipts as real authorization.**

```js title="make-inputs.mjs"
import { generateKeyPairSync, sign } from "node:crypto";
import { writeFileSync } from "node:fs";

const encode = (value) => Buffer.from(JSON.stringify(value)).toString("base64url");
const makeKey = () => {
  const { privateKey, publicKey } = generateKeyPairSync("ed25519");
  const jwk = publicKey.export({ format: "jwk" });
  const did = `did:jwk:${encode(jwk)}`;
  return { privateKey, did, kid: `${did}#0` };
};
const root = makeKey();
const agent = makeKey();
const now = Math.floor(Date.now() / 1000);
const jwt = (header, payload) => {
  const input = `${encode(header)}.${encode(payload)}`;
  return `${input}.${sign(null, Buffer.from(input), root.privateKey).toString("base64url")}`;
};
const payload = {
  iss: root.did, sub: agent.did, nbf: now - 60, exp: now + 3600,
  jti: "urn:uuid:0c535b28-c8ca-4a8d-8f8e-0cad21b56b77",
  vc: { "@context": ["https://www.w3.org/2018/credentials/v1"],
    type: ["VerifiableCredential"], credentialSubject: { age_over_18: true } },
};
const valid = jwt({ alg: "EdDSA", typ: "JWT", kid: root.kid }, payload);
const parts = valid.split(".");
// Change an issuer-signed claim WITHOUT re-signing: the signature must fail.
parts[1] = encode({ ...payload, vc: { ...payload.vc, credentialSubject: { age_over_18: false } } });
const unsupported = {
  "@context": ["https://www.w3.org/ns/credentials/v2"], type: ["VerifiableCredential"],
  issuer: root.did, validFrom: new Date((now - 60) * 1000).toISOString(),
  credentialSubject: { id: agent.did, age_over_18: true },
  proof: { type: "DataIntegrityProof", cryptosuite: "eddsa-rdfc-2022",
    verificationMethod: root.kid, proofPurpose: "assertionMethod", proofValue: "zUnsupportedExample" },
};
const requiredClaims = [{ path: "/credentialSubject/age_over_18", equals: true }];
for (const [name, credential] of Object.entries({ valid, tampered: parts.join("."), unsupported })) {
  writeFileSync(`${name}.json`, JSON.stringify({ credential, requiredClaims }));
}
const receipt = jwt({ alg: "EdDSA", typ: "didis-delegation+jwt", kid: root.kid }, {
  iss: root.did, aud: agent.did, cap: ["payments:refund"], nbf: now - 60, exp: now + 3600,
  jti: "synthetic-recipe-receipt",
});
const request = { chain: [receipt], tool: "payments:refund", trustedRoots: [root.did] };
for (const [name, body] of Object.entries({
  allow: request,
  "wrong-tool": { ...request, tool: "payments:transfer" },
  "untrusted-root": { ...request, trustedRoots: [agent.did] },
  "empty-chain": { ...request, chain: [] },
})) writeFileSync(`${name}.json`, JSON.stringify(body));
console.log("Created seven synthetic request files; private keys were not saved.");
```

The valid credential is a signed VC-JWT 1.1 with a synthetic age claim and **no revocation mechanism**. The tampered copy changes that claim without re-signing. The unsupported JSON input is deliberately not a valid signed credential: its proof value is an illustration, and its RDF cryptosuite is outside the supported verifier. This tests honest refusal, not RDF verification.

## Accept a partner's DID

**Job:** inspect an identifier before adding signature support to your integration. **Input:** the curated public `did:key` below; it is not a business partner. **Endpoint:** `GET /v1/resolve/{did}`. This self-certifying method derives its document without contacting an identifier's website; the client still makes an HTTP request to the API.

<Tabs syncKey="lang">
<TabItem label="curl">
```bash title="resolve.sh"
set -eu
: "${BASE:?Set BASE to your intended API base URL}"
curl --fail-with-body --silent --show-error --max-time 30 \
  "$BASE/v1/resolve/did:key:z6MkrJVnaZkeFzdQyMZu1cgjg7k1pZZ6pvBQ7XJPt4swbTQ2"
```
</TabItem>
<TabItem label="TypeScript">
```ts title="resolve.ts"
import { DidisClient } from "@didis/client";
const baseUrl = process.env.BASE;
if (!baseUrl) throw new Error("Set BASE to your intended API base URL");
const didis = new DidisClient({ baseUrl });
const r = await didis.resolve("did:key:z6MkrJVnaZkeFzdQyMZu1cgjg7k1pZZ6pvBQ7XJPt4swbTQ2");
console.log(JSON.stringify(r));
```
</TabItem>
<TabItem label="Python">
```python title="resolve.py"
import json, os
from didis import DidisClient
with DidisClient(base_url=os.environ["BASE"]) as didis:
    r = didis.resolve("did:key:z6MkrJVnaZkeFzdQyMZu1cgjg7k1pZZ6pvBQ7XJPt4swbTQ2")
print(json.dumps(r))
```
</TabItem>
</Tabs>

**Read the result:** `verdict.outcome` is `RESOLVED`; `didDocument.id` equals the input; `evidence.source.kind` is `LOCAL_DERIVATION`. The `integrity` dimension is `SELF_CERTIFYING`, while `origin` is `NOT_APPLICABLE` and `organization` is `NOT_ESTABLISHED`. This shows a derived document and usable key material, **not private-key possession, legal identity or domain ownership**. Reject unsupported methods or an unresolved identifier for integrations requiring resolution; never turn `RESOLVED` alone into a business-partner approval. For domain-based onboarding, use your own [policy rules](/build/policies/#rules) and a real partner's `did:web`, rather than expecting this key-only fixture to pass a domain-binding rule.

## Accept a credential

**Job:** distinguish an issuer-signed claim from a merely presented one. **Input:** `valid.json`, `tampered.json`, `unsupported.json` generated above. **Endpoint:** `POST /v1/credentials/verify`. First generate the files; then run one tab. Each sends three requests, printing one JSON response per line.

<Tabs syncKey="lang">
<TabItem label="curl">
```bash title="credential.sh"
set -eu
: "${BASE:?Set BASE to your intended API base URL}"
for name in valid tampered unsupported; do
  curl --fail-with-body --silent --show-error --max-time 30 \
    -X POST "$BASE/v1/credentials/verify" -H 'content-type: application/json' \
    --data-binary "@$name.json"
  printf '\n'
done
```
</TabItem>
<TabItem label="TypeScript">
```ts title="credential.ts"
import { readFileSync } from "node:fs";
import { DidisClient } from "@didis/client";
const baseUrl = process.env.BASE;
if (!baseUrl) throw new Error("Set BASE to your intended API base URL");
const didis = new DidisClient({ baseUrl });
for (const name of ["valid", "tampered", "unsupported"]) {
  const input = JSON.parse(readFileSync(`${name}.json`, "utf8"));
  const r = await didis.verifyCredential(input.credential, { requiredClaims: input.requiredClaims });
  const accept = r.status === "VALID" && r.requirements?.met === true;
  console.log(JSON.stringify({ name, accept, result: r }));
}
```
</TabItem>
<TabItem label="Python">
```python title="credential.py"
import json, os
from didis import DidisClient
with DidisClient(base_url=os.environ["BASE"]) as didis:
    for name in ["valid", "tampered", "unsupported"]:
        with open(name + ".json", encoding="utf8") as f:
            request = json.load(f)
        r = didis.verify_credential(request["credential"], required_claims=request["requiredClaims"])
        accept = r["status"] == "VALID" and (r.get("requirements") or {}).get("met") is True
        print(json.dumps({"name": name, "accept": accept, "result": r}))
```
</TabItem>
</Tabs>

**Expected decisions (B):** `valid` → `VALID`, `requirements.met: true`, claim condition `SATISFIED`; `tampered` → `INVALID`, not accepted; `unsupported` → `UNSUPPORTED`, not accepted. In the valid result the signature check passes, but revocation is `SKIP` because no status mechanism was declared. **`VALID` does not mean “not revoked” in this fixture.** `/credentialSubject/age_over_18` is the claim path exposed by this VC-JWT profile, not a universally valid path for every credential. The condition checks a signed statement, not a person's actual age. No expected audience was supplied, and this example does not verify that a presenter controls the subject key. Decide separately which issuers and status policies you trust. `INDETERMINATE`, `NOT_DISCLOSED`, network errors and absent requirements are never a pass; request missing evidence or stop. See [Credentials](/build/credentials/#overall-status).

## Allow an agent's tool call

**Job:** stop a tool call unless a signed delegation from a root you selected allows it. **Input:** a fresh, one-link synthetic chain and three negative variants. **Endpoint:** `POST /v1/agents/authorize`. No tool is invoked, no receipt is registered and no refund occurs. First generate the files, then run one tab (four requests).

<Tabs syncKey="lang">
<TabItem label="curl">
```bash title="authorize.sh"
set -eu
: "${BASE:?Set BASE to your intended API base URL}"
for name in allow wrong-tool untrusted-root empty-chain; do
  curl --fail-with-body --silent --show-error --max-time 30 \
    -X POST "$BASE/v1/agents/authorize" -H 'content-type: application/json' \
    --data-binary "@$name.json"
  printf '\n'
done
```
</TabItem>
<TabItem label="TypeScript">
```ts title="authorize.ts"
import { readFileSync } from "node:fs";
import { DidisClient } from "@didis/client";
const baseUrl = process.env.BASE;
if (!baseUrl) throw new Error("Set BASE to your intended API base URL");
const didis = new DidisClient({ baseUrl });
for (const name of ["allow", "wrong-tool", "untrusted-root", "empty-chain"]) {
  const input = JSON.parse(readFileSync(`${name}.json`, "utf8"));
  const r = await didis.authorize(input.chain, input.tool, { trustedRoots: input.trustedRoots });
  const accept = r.authorization.decision === "ALLOW" && r.authorization.authorized === true;
  console.log(JSON.stringify({ name, accept, result: r }));
}
```
</TabItem>
<TabItem label="Python">
```python title="authorize.py"
import json, os
from didis import DidisClient
with DidisClient(base_url=os.environ["BASE"]) as didis:
    for name in ["allow", "wrong-tool", "untrusted-root", "empty-chain"]:
        with open(name + ".json", encoding="utf8") as f:
            request = json.load(f)
        r = didis.authorize(request["chain"], request["tool"], trusted_roots=request["trustedRoots"])
        verdict = r["authorization"]
        accept = verdict["decision"] == "ALLOW" and verdict["authorized"] is True
        print(json.dumps({"name": name, "accept": accept, "result": r}))
```
</TabItem>
</Tabs>

**Expected decisions (B):** `allow` → `authorization.decision: ALLOW`, `chain.status: VALID`, `chain.trustedRoot: true`, one signature-verified link and `matchedCapability: payments:refund`. `wrong-tool`, `untrusted-root` and `empty-chain` → `DENY`, `authorized: false`. The root allowlist is essential: you chose it; resolving a DID does not make it trusted. This proves scoped delegation, **not safe agent behavior or the correctness of a refund**. Receipts are an experimental DID.is format, not a ratified standard. At your gateway, run the tool only after `ALLOW`; stop on denial, timeout, HTTP error or an unknown verdict. Regenerate expired inputs; multi-link attenuation, replay prevention and a real tool gateway are outside this one-link example. See [Authorise a tool call](/build/agents/#authorise-a-tool-call).

## When something goes wrong

The curl tabs print full responses; apply the same fail-closed decisions described above before invoking any application action. Native JSON HTTP API errors are problem objects with a stable `code`; W3C, SSE and MCP use different envelopes (see [Error formats by transport](/build/errors/#error-formats-by-transport)). The SDKs raise `DidisError`; read `status`, `problem.code` and `problem.detail`. An exception aborts these programs without an acceptance result. See [Errors and rate limits](/build/errors/) for every code.
